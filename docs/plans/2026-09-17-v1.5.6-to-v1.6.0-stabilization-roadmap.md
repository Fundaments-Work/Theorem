## 1. Executive Strategy & Guiding Decisions

Theorem's roadmap from **v1.5.5 to v1.6.0** is focused on **rock-solid stability, native performance parity, and universal knowledge extensibility**:

### 1.1 Fast Reading vs. Bionic Reading Clarification
- **Fast Reading Mode (RSVP / Speed Read - Built-in)**: Theorem already includes an RSVP (Rapid Serial Visual Presentation) mode in `src/features/reader/components/SpeedReaderModal.tsx`. RSVP flashes words sequentially at a fixed visual focal point at 300–800+ WPM, eliminating saccadic eye movement and sub-vocalization fatigue. This feature is preserved and accessible via reader controls.
- **Bionic Reading (Dropped from Roadmap)**: Bionic reading alters page typography by artificially bolding the initial syllables of every word (e.g., **The**orem **del**ivers **fas**ter **read**ing). Because Theorem readers prioritize clean, unadorned typography and Theorem already provides native RSVP speed reading, artificial font bolding adds visual noise and DOM complexity without verifiable comprehension benefits. It is dropped from the roadmap.

### 1.2 Spaced Repetition: Theorem Lemma SRS vs. Anki Exporter
- **Lemma SRS Integration**: Theorem's vocabulary workspace already synchronizes terms and definitions with **Lemma**, our companion spaced-repetition tool.
- **No Redundant Anki Exporter**: Rather than maintaining an isolated Anki `.apkg` generator that fragments development focus, vocabulary and highlights are exported as clean, standard Markdown that any flashcard tool or the Lemma companion can consume directly.

### 1.3 Universal PKM / Markdown Systems & Knap AST Templating
- Theorem is not an "Obsidian-only" reader. It is the premier reading hub for **all Markdown-based Personal Knowledge Management (PKM) systems**, including **Obsidian, Logseq, Foam, SilverBullet, Anytype, Dendron, Joplin, and plain Neovim/Emacs directories**.
- All note and highlight exports use standard Markdown, standard YAML frontmatter (`---`), and portable callouts (`> [!note]`, `> [!quote]`). In **v1.6.0**, **`knap`** (Obsidian's AST template engine) will provide a secure, sandboxed template compiler allowing users to format notes according to any tool's preferred schema with Markdown-native filters (`wikilink`, `callout`, `date`, `yaml`).
- **Deferred Items**:
  - *Branded Theorem Web Clipper*: While `obsidian-clipper` is MIT-licensed, creating a custom-branded Theorem Web Clipper browser extension is deferred alongside the WebAssembly plugin system until core reading and sync are stabilized.
  - *Web Article & RSS Vault Export*: Exporting clipped web articles and RSS feeds directly into vault note files is deferred until native Rust article extraction and book highlight vault sync are verified in production.

### 1.4 Strict Architectural Separation from Plugins
- In accordance with core engineering principles, **plugin extensibility is strictly separated from the core stabilization roadmap**. Core reading, PDF rendering, SQLite database virtualization, and P2P sync must achieve 100% native stability before any third-party sandbox is opened.
- All WebAssembly plugin ecosystem architecture is maintained in its own dedicated document: [`docs/plans/2026-08-30-plugin-extensibility-architecture.md`](./2026-08-30-plugin-extensibility-architecture.md).

### 2.1 PDF Engine Technical Details (`src/features/reader/engines/pdfjs-engine.tsx`)

1. **Pre-Fetched Structure & Virtual Tops**:
   - `prefetch_pdf_structure` (Rust Tauri command) parses the PDF trailer and root catalog in <5ms, returning `total_pages`, `default_width_pt`, and `default_height_pt`.
   - `computeVirtualPageTops()` calculates an immutable `Float64Array` containing exact scroll positions for all $N$ pages.
   - Placeholders are registered with an `IntersectionObserver` to trigger concurrent proxy loading (`PAGE_PROXY_LOAD_CONCURRENCY = 3`) as pages approach the viewport.

2. **Two-Page Spread (Facing Pages)**:
   - Chunked via `getSpreads(totalPages)`: Spread $k$ is `[2k - 1, 2k]` (e.g. `[1, 2]`, `[3, 4]...`), allowing facing page reading to start immediately on page 1.
   - Each spread row renders `<div className="pdf-spread-row flex flex-row flex-nowrap items-center gap-2 sm:gap-4 my-1 sm:my-2 mx-auto">` with CSS `width: max-content; min-width: 100%; justify-content: safe center;`.
   - The `.pdf-zoom-container` uses `width: max-content; min-width: 100%; margin: 0 auto;`, eliminating centering overflow data loss so the entire left page is visible from $x = 0$ with full horizontal panning and zoom support.
   - `getFitWidthScale(container, page, isTwoPage)` and `getFitPageScale(container, page, isTwoPage)` divide container width by 2 (minus horizontal spread gap) to automatically fit facing pages on widescreen monitors.
   - Next/previous actions (keyboard ArrowLeft/ArrowRight, PageUp/PageDown, boundary-aware touch swipe, edge tap zones) advance by spread in two-page mode without interrupting horizontal panning.

3. **Active TOC Outline Synchronization**:
   - `activePdfTocHref` in `Reader.tsx` continuously scans the table of contents tree to locate the latest chapter where `chapterPage <= pdfCurrentPage`.
   - Avoids the pitfall where TOC highlights vanish as soon as the user scrolls past the first page of a chapter.

4. **Search Match Focus Rings**:
   - `PageCanvas` receives `searchQuery`. When text layer rendering finishes, a DOM walker extracts matching text spans and wraps them with `.pdf-search-match`.
   - CSS rules apply `box-shadow: 0 0 0 1.5px var(--color-accent)`, semi-transparent accent background, and subtle pulsing focus ring, respecting `prefers-reduced-motion`.

5. **Fullscreen Overlay Chrome & Stacking Context Isolation**:
   - Viewport containers in `Reader.tsx`, `ArticleViewer.tsx`, and `ReaderViewport.tsx` remain fullscreen `absolute inset-0 z-0 isolate`, completely decoupled from toolbar or navbar visibility.
   - Prevents EPUB column re-pagination, page jumping, or reflow bugs caused by dynamic viewport dimension resizing.
   - `WindowTitlebar` and `ReaderNavbar` operate as floating HUD overlays rendered at `z-[140]`, gliding smoothly over the content via GPU-accelerated `translate-y` transforms without affecting reading layout.

## 3. Core Architectural Subsystems & High-Performance Rust Foundations

### 3.1 Cloudflare-Inspired Rust Data Layouts
To eliminate memory fragmentation and heap overhead across Theorem's native core, we adopt Cloudflare's high-performance memory layout principles:

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│                           CLOUDFLARE RUST DATA LAYOUT PRINCIPLES                                │
├──────────────────────────┬──────────────────────────────────────────────────────────────────────┤
│ TECHNIQUE                │ APPLICATION IN THEOREM                                               │
├──────────────────────────┼──────────────────────────────────────────────────────────────────────┤
│ 1. Box<[T]> & Box<str>   │ Used for all immutable DTOs (RSS articles, OPDS entries, book        │
│    (Cost of Capacity)    │ search results). Drops 8B capacity per field; zero heap slack.       │
│ 2. Contiguous Flattening │ Replace multiple heap vectors with flat buffers indexed by u16       │
│    (Fewer Lists/Pointers)│ offsets. Pack boolean flags into bitflags structs.                   │
│ 3. Context-Inferred Keys │ Child records (e.g. RSS articles, highlights) omit redundant parent  │
│    (Dropping the Owner)  │ IDs (feed_id, book_id) in memory if known by the query context.      │
│ 4. Enum Variant Boxing   │ Box large/rare enum variants (clippy::large_enum_variant) to shrink  │
│    (Enum Sizing)         │ the entire enum to ≤24 bytes.                                        │
│ 5. Scratchpad Buffers    │ Thread-local reusable serialization scratchpads with exact memcpy    │
│    (Wire Format Packing) │ into Box<[u8]>. Zero-copy IPC transfer.                              │
└──────────────────────────┴──────────────────────────────────────────────────────────────────────┘
```

### 3.2 Modern Relational RSS Subsystem
- **Native Streaming Parser (`src-tauri/src/rss_parser.rs`)**: Zero-copy SAX parsing over byte streams using `quick-xml`. Parses feeds in 2–5ms (vs. 150–400ms in JavaScript), shedding ~175KB of minified JS from the frontend bundle.
- **Relational Content Decoupling (`src-tauri/src/database.rs`)**:
  - `rss_feeds` & `rss_articles`: Store lightweight metadata (~200 bytes per article).
  - `rss_article_content`: Stores heavy HTML content, fetched strictly on-demand when an article is opened.
  - Eliminates the 25MB monolithic persist loop from `rssStore.ts`.
- **Native Readability (`src-tauri/src/article_extractor.rs`)**: Rust-native article extraction from raw HTML.

### 3.4 In-Book Search & Audio Processing
- **Zero-Allocation Search Snippets (`src-tauri/src/book_search.rs`)**: Uses `char_indices()` byte-slicing instead of `Vec<char>` allocations, speeding up in-book search by 10× with 0 transient heap bytes.
- **Native PDF Search (`search_book_content`)**: High-speed parallel PDF object stream parser that extracts text and yields matches with `pdf:page:X` locations.
- **Native WSOLA Time-Stretching (`src-tauri/src/audio_player.rs`)**: High-quality pitch-preserving waveform similarity overlap-add algorithm for 0.5×–3.0× narration speed adjustment.

### 3.5 P2P Sync Hardening (`theorem-sync-core`)
- **Granular Item-Level Sync Keys**: Transition from monolithic array keys (`annotations`) to atomic keys (`anno:<bookId>:<annotationId>`), eliminating Last-Write-Wins (LWW) array clobbering during concurrent offline editing.
- **Native In-Database Gossip Merge (`sqlite_merge_sync_entries`)**: Applies incoming Iroh-gossip updates directly to SQLite in a single transaction.
- **Multi-Mount Drive Normalization**: Extended Tauri asset protocol and file resolution to support external storage (`/run/media/**/*`, `/media/**/*`, `/mnt/**/*`).

## 5.2 Deep Dive: v1.5.7-BETA Implementation Plan (Consolidated Work Packages)

### Work Package 1: Note Export Typography & Knap AST Template Engine
- **Problem**: Exported Obsidian notes currently contain bloated and redundant metadata in the YAML frontmatter (`annotations_total`, `highlights_total`, `notes_total`, internal `format`, and absolute `source_path`). The Markdown body uses artificial numbered headings (`### 1. Highlight`), redundant color labels (`- Color: yellow` when Obsidian only highlights yellow), and cluttered timestamps (`- Created: ...`), with noisy horizontal rules between every item.
- **Knap Evaluation & Binary Footprint**:
  - `@obsidianmd/knap` is an official TypeScript library created by Obsidian (Steph Ango / kepano).
  - **Binary size impact**: **0 bytes** on the native Rust binary (Tauri does not bundle npm libraries into the Rust binary). Only ~12KB gzipped in the webview bundle, loaded strictly on-demand when the export modal is accessed.
  - **Functionality**: Provides safe, sandboxed Markdown template compilation without `eval()`, enabling custom user templates (`> [!quote]`, `[[wikilinks]]`, custom frontmatter) while retaining full Obsidian compatibility.
- **Implementation**:
  1. In `src-tauri/src/vault_export.rs` (`build_book_page_markdown`) and `src/core/lib/vault-sync.ts`:
     - Clean YAML frontmatter: keep only `title`, `author`, `type: "theorem-book-highlights"`, single `total_highlights: N`, and `tags: [theorem, highlights]`.
     - Remove `format`, `source_path`, `generated_at`, and redundant duplicate counts.
     - Clean body: `# Title`, `*Author*`, `## Highlights`.
     - Clean highlights: format quotes as simple Markdown blockquotes (`> ==Text==`) followed immediately by user notes if present. Remove `### 1. Highlight` numbering, dates, colors, and divider lines.
  2. Integrate `@obsidianmd/knap` for custom user template parsing in frontend export settings.
  3. Ensure Rayon in `vault_export.rs` continues to handle parallel disk writes in microseconds.

### Work Package 2: Sync Deletion Tombstones & Ghost Book Elimination
- **Problem**: When a book is deleted on one peer, other paired peers retain the stale book card in their library because `deletion_tombstones` are merged into SQLite but not reconciled against the active in-memory Zustand library state. When the user taps the stale card, on-demand download requests the file from the source peer, which fails with `peer error: book not found`.
- **Implementation**:
  1. In `src/core/lib/sync-orchestrator.ts` (`reconcileWithStore`), after `sqlite_merge_sync_entries` completes, query local `deletion_tombstones` and filter out matching books from `useLibraryStore.getState().books`.
  2. In `src-tauri/src/file_transfer.rs` (`locate_book`), check if `book_id` exists in the `deletion_tombstones` table or has `deletedAt` set. If so, return a distinct error `Err(format!("book '{book_id}' has been deleted on this device"))`.
  3. In `Reader.tsx`, if on-demand download returns that the book was deleted on the peer, immediately trigger `useLibraryStore.getState().removeBook(currentBookId)` and navigate back to the Library with an informative toast (`"This book was deleted on the source device."`).

### Work Package 3: SQLite Memory Reclaim & Android `onTrimMemory`
- **Problem**: SQLite holds onto dirty page buffers and connection memory indefinitely unless told to release them. On Android, running in the background without trimming memory causes the OS LMK (Low Memory Killer) to terminate the app.
- **Implementation**:
  1. In `src-tauri/src/lib.rs` (`trim_memory`), execute `PRAGMA shrink_memory;` and `PRAGMA wal_checkpoint(PASSIVE);` on the SQLite connection pool alongside `libc::malloc_trim(0)`.
  2. In `src-tauri/plugins/android-tts-audio` or `MainActivity.kt`, register a `ComponentCallbacks2` listener:
     ```kotlin
     override fun onTrimMemory(level: Int) {
         super.onTrimMemory(level)
         if (level >= ComponentCallbacks2.TRIM_MEMORY_UI_HIDDEN) {
             // Dispatch event to Tauri runtime to call trim_memory
             triggerTauriTrimMemory()
         }
     }
     ```
  3. Reclaim unused WebP image caches and disconnect inactive Iroh endpoints when hidden.

### Work Package 4: Foliate Section Resource Cleanup (LRU)
- **Problem**: In long reading sessions of illustrated books, comics, or manga, Foliate creates `blob:` URLs for each chapter's images. These remain held in WebView graphics memory, gradually increasing WebView RSS beyond 400MB.
- **Implementation**:
  1. In `src/features/reader/foliate-js-runtime/view.js`, maintain a tracked set of active section `blob:` URLs.
  2. When navigating between chapters, revoke URLs for sections that are more than 2 chapters away from the active viewport (`URL.revokeObjectURL(url)`).
  3. Caps WebView graphics memory to $\le 120$MB regardless of session length.

### Work Package 5: Android Hardware Back Button & Lockscreen MediaSession
- **Problem**: Tapping Android's system back button closes the application directly rather than dismissing open modals (TOC, Settings, Search, Bookmarks) or returning from Reader to Library. TTS playback stops when the screen is locked.
- **Implementation**:
  1. In `src/App.tsx`, listen to `@tauri-apps/api/event` or `appWindow.onCloseRequested` / Android back event:
     - If a reader panel or modal is open $\rightarrow$ close the panel.
     - If in Reader view $\rightarrow$ navigate to Library route (`setRoute('library')`).
     - If in Library view $\rightarrow$ allow default OS minimize/exit.
  2. *(Moved to v1.6.x — see §8)* In `TtsAudioPlugin.kt`, attach `MediaSessionCompat` with playback state and request `AudioManager.AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`, allowing immersion narration to proceed smoothly on screen-off.

### Work Package 6: Native Rust Readability Engine
- **Problem**: Theorem currently relies on `@mozilla/readability` and `DOMPurify` in the webview, adding JavaScript execution overhead and bundle weight. The existing Rust fallback in `article_extractor.rs` uses simplistic string finding.
- **Implementation**:
  - Adopt proven, battle-tested Rust crates (e.g. `readability` / `scraper`) rather than hand-crafting DOM parsing algorithms.
  - Parse article HTML directly in Rust, extract title, text content, reading time, and lead image, and return clean sanitized HTML/Markdown to the frontend.
  - Purge `@mozilla/readability` and `dompurify` from `package.json`.

### Work Package 7: Subnet mDNS Peer Discovery
- **Problem**: P2P sync relies on Iroh relay nodes when discovery tickets are exchanged, creating unnecessary network hops on local LANs.
- **Implementation**:
  - Implement zero-relay local peer discovery via mDNS / local multicast broadcast in `theorem-sync-core`.
  - Directly connect to paired local peers over LAN QUIC sockets in <100ms.

### Work Package 8: Relational Library Store Migration & PDF Thumbnail Drawer
- **Problem**: Serializing 5,000+ books into a single monolithic JSON string in `zustand:theorem-library` slows down serialization and causes memory overhead during state updates. In PDFs, users need visual thumbnail overview navigation.
- **Implementation**:
  - Migrate book metadata from `kv_store` JSON to the dedicated SQLite `book_metadata` table.
  - Provide a responsive PDF sidebar thumbnail drawer powered by `prefetch_pdf_structure` and `@tanstack/react-virtual`.

## 7. Reading System Stabilization (v1.6.0 Primary Focus — added 2026-09-23)

The v1.6.0 stable release is gated on the reader, not on new features. Every reading path (PDF, EPUB/MOBI/FB2/CBZ, article reader) must be fast, smooth and complete. The PDF reader's reference bar is **GNOME Papers / Evince** and **Mozilla's pdf.js viewer** (Firefox): anything a reader expects from those must work in Theorem.

### 7.1 PDF — Gap Audit (verified against `src/features/reader/engines/pdfjs-engine.tsx`, 2026-09-23)

**P0 — Broken / missing core behavior**
- [ ] **Link annotation layer**: `page.getAnnotations()` is never called, so PDFs have *no* clickable links — internal links (in-document TOC, `[12]` citations, footnote markers, "see Fig. 3", equation refs) and external URLs are all dead. Build a lightweight link layer (render `Link` annotations as absolutely positioned anchors per page, resolved via `getDestination` / `getPageIndex`, reusing the existing outline resolver).
- [ ] **Theorem Lens for PDF (citation / footnote hover)**: `FootnotePopover` is wired to Foliate only. On hover (desktop) / tap (mobile) of an internal link, resolve the destination (page + XYZ coordinates), extract the target text block from the destination page's text content (reference entry, footnote, figure caption) and show it in the Lens popover with a "Jump" action. Fallback: render a clipped canvas snippet of the destination region when text extraction yields nothing.
- [ ] **JBIG2 / JPEG 2000 / ICC decoding**: pdf.js 6 decodes JBIG2 and JPX images via WASM loaded from `wasmUrl`; we pass neither `wasmUrl` nor `iccUrl` and don't ship `node_modules/pdfjs-dist/wasm` (1.6 MB) or `iccs/`. Result: images in scanned books (JBIG2) and many scientific papers (JPX) render blank, and CMYK/ICC colors are wrong. Copy `wasm/` + `iccs/` in `vite.config.ts` and pass `wasmUrl` / `iccUrl` in `commonPdfOptions`.
- [ ] **Navigation history (Back / Forward)**: After following a link or TOC entry there is no way back to where you were reading. Add a position stack (Alt+←/Alt+→, mouse back/forward buttons, a transient "Back to p. N" pill after any jump).

**P1 — Smoothness (Papers / Firefox parity)**
- [ ] **Zoom without blur-then-pop**: Ctrl+wheel and pinch currently commit a full re-render every ~90 ms. Keep the CSS-transform preview for the whole gesture, keep the old canvas visible until the new one is ready (double buffer), and re-render only visible pages at the final scale.
- [ ] **Progressive rendering**: Draw a low-resolution pass first for pages entering the viewport during fast scroll/scrollbar drags, then refine — no white pages while flinging through a 1,000-page PDF.
- [ ] **Anchored zoom everywhere**: Zoom keyboard shortcuts / toolbar keep the point under the viewport center fixed (wheel and pinch already anchor).
- [ ] **Frame-time budget**: Profile scroll on a 1,000-page scanned PDF and a vector-heavy paper on Linux WebKitGTK and Android; target no long tasks > 50 ms during scroll, and no layout thrash from text-layer calibration.
- [ ] **Visual Thumbnail Drawer** (existing item, §4.1): virtualized sidebar thumbnails rendered at low scale from a dedicated low-priority render queue.

**P2 — Expected reader features**
- [ ] **Page labels**: `getPageLabels()` is unused — show logical labels (`xii`, `A-3`) in the page indicator and accept them in "go to page".
- [ ] **Dark / sepia themes for PDF**: `theme` is accepted by `PDFReader` but never applied. Add pdf.js-style page color override (invert with image-preserving hue rotation, or `pageColors` foreground/background for text-only pages).
- [ ] **Find bar parity**: match-case / whole-word toggles, "N of M" counter, F3 / Shift+F3 / Enter cycling across pages.
- [ ] **Double-click word / triple-click line selection** and copy fidelity (ligatures, hyphenation, column order) verified on WebKitGTK.
- [ ] **Document properties** (`getMetadata()` → title, author, producer, page size, PDF version) in the book info popover.
- [ ] **Presentation / fullscreen single-page mode** and **Print** (desktop).
- [ ] **Embedded attachments** (`getAttachments()`) listing — low priority.

### 7.2 EPUB / Reflowable & Article Reader — Gap Audit (2026-09-23)

**P0**
- [ ] **Highlight re-render storm**: `FoliateEngine.renderAnnotationsForSection(_sectionIndex)` ignores its index and re-adds *every* annotation in the book; it fires twice per section load (`create-overlay` + `load`) and on every `selection` relocate, and `loadAnnotations` calls it once per visible section. Each call runs `resolveNavigation(cfi)` (CFI parse) per annotation. A book with 1,000 highlights costs ~2,000+ CFI resolutions and overlay remove/add cycles per chapter turn. Fix: index annotations by spine section (from the CFI's first step) and render only the loaded section, once.
- [ ] **Zoom / restyle flash on open and chapter turns — WebKitGTK only (Linux desktop)**: not reproducible on Android WebView or in desktop browsers (Chromium/Firefox), so it is a WebKitGTK paint/compositing quirk rather than a layout-logic bug. Fix attempts `155fd07` / `116fc0e` changed shared restyle timing and were reverted in `96aad64`. Any fix must be gated to desktop WebKit (the engine already has an `isDesktopWebKit` path for PDF) so Android and web behavior stay byte-identical. Candidates: keep the section iframe hidden (`visibility`/`opacity`, not `display`) until the post-zoom `render()` settles on WebKitGTK only; avoid the `applyZoomSync` → `renderer.render()` → `_retryIfBrokenLayout` double pass there; check whether the flash is a composited-layer drop (try `will-change: transform` / `contain: paint` on the paginator container under WebKitGTK).

**P1**
- [ ] **Whole-file EPUB load**: `getBookData` reads the entire book over IPC into JS memory, then `bookModelCache` (limit 2) keeps up to two whole books resident. PDFs already use range reads (`TauriPdfRangeTransport`); give EPUB the same, a `Blob`-like lazy reader backed by a native range/entry command, so large illustrated EPUBs/CBZ don't spike the WebView heap (critical on Android).
- [ ] **Reader.tsx re-render cost**: a 2,933-line component with 57 `useState`s; `setLocation` on every relocate re-renders all of it. Move location/progress into a small store slice that only the navbar/progress/TOC subscribe to; profile page-turn commit time before and after.
- [ ] **Remove the `@mozilla/readability` + `dompurify` fallback** in `ArticleExtractorService.ts` (readability plan, Phase 1). `dompurify` is also used by `src/core/lib/sanitize.ts` (4 call sites), so it needs a Rust sanitizer (e.g. `ammonia`) or an explicit decision to keep it for display sanitizing.

**P2**
- [ ] **Page-turn WPM sampling**: `handleLocationChange` calls `recordPageTurn()` then `recordPageTurn(words)` 1 s later; the second call resets `lastPageTurnTimeRef`, so every dwell is measured 1 s short (WPM slightly overestimated). Record once with the sampled word count.
- [ ] Linear `annotations.find(...)` scans in `Reader.tsx` selection/annotation paths → use the existing `Map` lookup.

### 7.3 Other Subsystems — Stability & Performance Audit (2026-09-23)

**Persistence & Database**
- [ ] **P0 — Close-time data loss (desktop)**: on `beforeunload` the pending persist writes are flushed to **localStorage**, but on the next launch `theoremPersistStorage.getItem` reads SQLite first and only falls back to localStorage when SQLite has no value. Any change made in the last ~350 ms + idle window before quitting (last page position, a new highlight) is silently dropped, and a stale localStorage copy lingers indefinitely. Fix: flush to SQLite from `onCloseRequested` (await, then close), and on startup reconcile a newer unload snapshot before clearing it.
- [ ] **P1 — Relational library store** (existing item §4.3): books + all annotations still live in one JSON blob (`theorem-library` v6); every progress update rebuilds `books.map(...)` in `partialize` and re-stringifies the whole library. `sqlite_query_books_window` exists but has no callers.
- [ ] **P1 — Dual-write without a source of truth**: vocabulary (`vocabulary` table) and annotations (`book_annotations`) are written to both SQLite and the JSON blob; on load, vocabulary merges by "add ids missing from JSON", so a term whose SQLite delete failed comes back. Make SQLite authoritative and drop these arrays from the JSON blob.

**Library / Book Browser**
- [ ] **P0 — Cover memory**: on startup every book's cover is fetched one IPC call at a time and stored as a **base64 data URL** in the `books` array (and in SQLite as text). Thousands of books means tens of MB of JS heap before the grid appears. Serve covers as files through the asset protocol (`convertFileSrc`) and load them lazily for visible cards only.
- [ ] **P2**: JS fuzzy fallback in `library/filtering.ts` (browser path) — acceptable for web, but make sure desktop and Android always take the FTS5 + nucleo path.

**RSS**
- [ ] **P1 — Favorites silently disappear**: `partialize` keeps only articles < 30 days old and the first 500, with no exemption for `isFavorite`; SQLite still has them, but the list is never reloaded from SQLite, so favorites vanish after a restart. Load the article list from `rss_articles` (SQLite is already written) and keep favorites.
- [ ] **P2**: `refreshAll` fires every feed concurrently (`Promise.allSettled(feeds.map(...))`) — cap concurrency (4–6); markdown→HTML conversion (`markdown-it`) runs in JS for every article — move it into the Rust RSS parser.

**Statistics & Goals**
- [ ] **P1 — UTC day boundaries**: daily activity, streaks, "today" and the Rust goal reminder (`check_goal_reminder_inner`) all use UTC dates (`toISOString().split('T')[0]` / `SystemTime`). Reading in the evening in UTC−X, or early morning in UTC+X, lands on the wrong day. Switch to local-date keys end to end (with a one-time migration of existing keys, or accept the historical offset).

**Sync**
- [ ] **P1 — Vocabulary merge write amplification**: each incoming vocabulary merge compares full arrays via `JSON.stringify` and then calls `sqliteSaveVocabularyTerm` for **every** term (one IPC each). Diff and batch-write only changed terms.
- [ ] **P2**: `rss_articles` is synced as one full JSON domain blob; annotation conflict detection does nested `JSON.stringify` + `incoming.some(...)` per changed annotation — index by id.
- [ ] mDNS (§4.3) is already live via `iroh-mdns-address-lookup` (`iroh_sync.rs:163`); tick after confirming LAN transfer latency.

**Vault / PKM Export**
- [ ] **P1 — Full rewrite on every change**: any highlight/vocab change triggers `vault_export_snapshot`, which rewrites **every** note file (plus a vocabulary file that embeds `generated_at`, so it always differs). This churns Obsidian's indexer and file-sync tools (Syncthing, Obsidian Sync). Skip writes when the content is byte-identical, and move `generated_at` out of the body.
- [ ] **P1 — Orphaned notes**: no cleanup pass — renaming a book or deleting its last highlight leaves the old `.md` file forever. Track exported files (manifest) and remove or rename stale ones.
- [ ] Knap integration (re-opened, see §4.5) → PKM presets → template editor.

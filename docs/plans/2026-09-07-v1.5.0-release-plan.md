# v1.5.0 Release Plan — Polish, Visibility & Performance

**Date**: 2026-09-07 · **Status**: Active · **Target Version**: v1.5.0

This release plan focuses on fixing key usability, visibility, and performance issues discovered after the v1.4.0 release, eliminating build warnings, and optimizing frontend and native pipelines.

---

## 1. Release Goals

1. **Android TTS Companion Visibility**: Ensure Theorem Neural Voice companion app (`work.fundamentals.theorem.neuralvoice`) is detected and selectable on Android 11+ ([#71](https://github.com/Fundaments-Work/Theorem/issues/71)).
2. **Instant Highlighting Responsiveness**: Eliminate the latency and fast-path failure when creating or clicking highlights in the reader ([#72](https://github.com/Fundaments-Work/Theorem/issues/72)).
3. **CLI Argument Routing**: Ensure top-level flags (`--help`, `-h`, `--version`, `-V`, `help`) run in terminal without launching the GUI window.
4. **Build & Bundle Hygiene**: Eliminate dynamic import bundler warnings, split heavy frontend chunks (<500 kB), modernize Rust 1.98 slice chunking, and update deprecated CI actions.

---

## 2. Implementation Phases

### Phase 1: Android TTS Package Visibility & Companion Integration (Issue #71)
- **Problem**: Android 11+ (API 30+) restricts inter-process package visibility. Without declaring `<queries>`, `TextToSpeech.getEngines()` conceals third-party TTS engines, showing only the pre-installed system engine.
- **Tasks**:
  - [x] Add the package query declaration to `src-tauri/gen/android/app/src/main/AndroidManifest.xml`:
    ```xml
    <queries>
        <intent>
            <action android:name="android.intent.action.TTS_SERVICE" />
        </intent>
    </queries>
    ```
  - [x] Also add the `<queries>` declaration to `src-tauri/plugins/android-tts-audio/android/src/main/AndroidManifest.xml` so the plugin provides manifest merging out of the box.
  - [x] Verify in `NeuralVoiceSection.tsx` that Theorem Neural Voice appears in the engine selection dropdown and can be set as active engine.

### Phase 2: Instant Highlighting & Annotation Map Sync (Issue #72)
- **Problem**: In `src/features/reader/engines/foliate-engine.ts`, `this.annotationLocations` is only populated during `loadAnnotations()`. Creating a highlight via `addHighlight()` or `addAnnotation()` omits updating the map, causing clicking to miss the fast-path and fall back to slow DOM traversal and synthetic timeouts.
- **Tasks**:
  - [x] In `addHighlight()`: call `this.annotationLocations.set(annotation.location, annotation)`.
  - [x] In `addAnnotation()`: call `this.annotationLocations.set(annotation.location, annotation)`.
  - [x] In `removeHighlight()`: remove from `this.annotationLocations.delete(annotation.location)`.
  - [x] Audit event listener attachment on the SVG highlight groups (`click`, `touchend`, `pointerup`) to prevent duplicate activations and redundant layout recalculations (added 300ms deduplication).
  - [x] Verify instant (<16ms, single frame) popup opening when creating and immediately tapping a highlight.

### Phase 3: CLI Top-Level Flag & Subcommand Routing
- **Problem**: `maybe_dispatch` in `src-tauri/src/cli.rs` filtered out all arguments starting with `-`, causing `theorem --help` and `theorem --version` to fall through to `theorem_lib::run()` and open the GUI.
- **Tasks**:
  - [x] Update `maybe_dispatch` in `src-tauri/src/cli.rs` to intercept `--help`, `-h`, `--version`, `-V` directly in the CLI dispatcher.
  - [x] Ensure `theorem help` and `theorem help <command>` properly route to clap help generators.
  - [x] Test that invoking `theorem` with no arguments launches the GUI, while any CLI flag/subcommand remains completely headless in the terminal.

### Phase 4: Frontend Bundle & Build Warnings Cleanup
- **Tasks**:
  - [x] **Fix `[INEFFECTIVE_DYNAMIC_IMPORT]`**:
    - `src/features/share/ShareCardModal.tsx` statically imports `html-to-image`, defeating the dynamic import in `src/core/lib/share.ts`.
    - Change `ShareCardModal.tsx` to dynamically load `html-to-image` on click or route export calls through `share.ts`.
  - [x] **Chunk Code-Splitting**:
    - Update `vite.config.ts` with `manualChunks` in `build.rolldownOptions.output` to split `lucide-react` and large vendor packages into separate chunks, bringing the main bundle below 500 kB (dropped from 553 kB to 282 kB).
  - [ ] **Rust 1.98 Clippy Modernization**:
    - Update `.chunks_exact(2)` call sites in `src-tauri/src/audiobook_gen.rs` and `src-tauri/src/mdict.rs` to `.as_chunks::<2>().0.iter()`.
  - [ ] **GitHub Actions Modernization**:
    - Update workflows (`ci.yml`, `release.yml`, and `supertonic-android/release.yml`) to use `actions/checkout@v5`, `actions/setup-java@v5`, and `gradle/actions/setup-gradle@v5`.

### Phase 1 — Immersion streaming robustness (desktop) · medium ✅

The streaming neural player (first chunk plays while the rest synthesize)
needed three fixes for long pages and slow synthesis. Files:
`src-tauri/src/audio_player.rs`, `src-tauri/src/supertonic.rs`,
`src/features/reader/audio/ImmersionPlayer.ts`.

- [x] **Underrun guard**: the native player tracks per-chunk durations, so a
  drained queue reports the end of synthesized audio as the position (no
  reset/stall); appending the next chunk resumes seamlessly. The frontend
  holds the playing state through underruns. One-chunk-ahead synthesis is a
  no-op here — the engine mutex already serializes synthesis continuously.
- [x] **Cross-chunk progress/seek**: `tts_audio_position` returns
  `sum(finished chunk durations) + rodio get_pos()`; `tts_audio_seek` takes
  an absolute page position and re-queues the chunks from the target onward
  (preserving pause state) via rodio's `len()`/`clear()`/`is_paused()`.
- [x] **Next-page prefetch wiring**: `ImmersionPlayer.prefetch` now chunks
  the next page and prefetches its first two chunks (the synthesis cache is
  keyed per chunk — prefetching whole-page text was never a cache hit);
  `Reader.tsx` calls it via `getNextPageTextForTts` when immersion is on.

### Phase 2 — Release freshness guard · small ✅

- [x] Settings → About shows a Build row (git hash · commit date), baked at
  compile time by `src-tauri/build.rs` (`THEOREM_GIT_HASH` /
  `THEOREM_BUILD_DATE`) and exposed via the `app_build_info` command.
- [x] Refresh flow documented in `docs/settings.md` §About.

### Phase 3 — HUFF/CDIC MOBI decompression · medium ✅

- [x] Native Huffman decoder (`HuffCdic` in `mobi_parser.rs`) for
  compression-type-2 records, with synthetic round-trip tests (literal
  phrases, cross-reference recursion, multi-codelen mincode walk).
- [x] Bonus fix found while verifying against a real library book: the
  PalmDOC LZ77 distance was decoded with a 9-bit layout instead of the
  canonical 11-bit one — all real PalmDOC books with back-references
  extracted garbled text. Fixed; the Karamazov Brothers now extracts
  2,263,155 clean chars (was: "HUFF/CDIC not supported" error).
- [x] Books mislabeling compression 2 without HUFF/CDIC records fall back
  to PalmDOC decoding (the "at least one real library book" from the old
  CLI plan §9 is exactly this case).
- Known limitation: per-record trailing extra data (multibyte-overlap
  flags) is not stripped before decoding; surface if a real book shows
  garbage tails at record boundaries.

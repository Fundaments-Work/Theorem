# Signing Keys

This document describes how to generate and manage the two separate signing keys needed for
Theorem distribution: the **Tauri Updater key** (Ed25519) and the **Android APK key** (JKS).

---

## 1. Tauri Updater Signing Key (Ed25519)

The updater plugin signs AppImage, DMG, and NSIS `.exe` installer files so the app can verify
that updates come from a trusted source.

### Generate the keypair (requires interactive terminal)

```bash
pnpm tauri signer generate -w ~/.tauri/theorem.key
```

You will be prompted to enter a password (or leave empty for no password).
This command **requires a real TTY** — it won't work in non-interactive terminals
(like `opencode` or CI). Run it directly in your terminal.

This creates/updates:
- `~/.tauri/theorem.key` — **private key** (never share, keep safe)
- The public key is printed to stdout — copy it for `tauri.conf.json`

### Set the public key in tauri.conf.json

Open `src-tauri/tauri.conf.json` and verify (or rotate) the existing `plugins.updater.pubkey`, which is already populated with the project's minisign public key:

```json
{
  "plugins": {
    "updater": {
      "pubkey": "<paste the public key here>",
      "endpoints": [
        "https://github.com/fundaments-work/Theorem/releases/latest/download/latest.json"
      ]
    }
  }
}
```

### Store the private key for CI

Add the private key as a **GitHub Actions secret**:

1. Go to GitHub repo → Settings → Secrets and variables → Actions → Secrets
2. Create `TAURI_SIGNING_PRIVATE_KEY` with the **content** of `~/.tauri/theorem.key`
3. Create `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` with the password (if any)

The CI workflow (`release.yml`) already passes these to all `tauri-action` steps.

### Back up the key

Store `~/.tauri/theorem.key` in a secure location (password manager, encrypted USB, etc.).
**If you lose this key, existing users cannot receive future updates.**

### How the update server works

The updater endpoint points to:
```
https://github.com/fundaments-work/Theorem/releases/latest/download/latest.json
```

This `latest.json` file is **auto-generated by `tauri-action`** during CI builds when
`createUpdaterArtifacts: true` is set in `tauri.conf.json` (it is). The action:

1. Generates a `.sig` signature file for each installer
2. Creates `latest.json` with version, platform URLs, and signatures
3. Uploads everything to the GitHub release

**You don't need to create or host `latest.json` manually.** Just push a tag
(`v1.4.3`, etc.) and the CI pipeline handles it.



## 2. Android APK Signing Key (JKS)

Android requires all APKs to be signed with a keystore before installation or Play Store
upload. A JKS keystore is a file that contains cryptographic keys. It has two layers of
protection:

- **Keystore password** — unlocks the file itself
- **Key password** — unlocks the specific key inside (identified by alias)

They can be the same (press Enter when keytool asks for key password).

### Generate a new keystore

```bash
keytool -genkey -v \
  -keystore ~/theorem-android.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias theorem-release-key
```

You will be prompted for (in order):

| # | Prompt | What to enter |
|---|--------|---------------|
| 1 | Enter keystore password | Choose one, e.g. `theorem-sign` |
| 2 | Re-enter new password | Same again |
| 3 | What is your first and last name? | `Fundaments` |
| 4 | What is the name of your organizational unit? | (blank — press Enter) |
| 5 | What is the name of your organization? | `Fundaments` |
| 6 | What is the name of your City or Locality? | Your city |
| 7 | What is the name of your State or Province? | Your state |
| 8 | What is the two-letter country code? | e.g. `US`, `NP`, `IN` |
| 9 | Is CN=Fundaments... correct? | `yes` |
| 10 | Enter key password for \<theorem-release-key\> | **Press Enter** to use same as keystore password |

Take note of these — you'll need them for GitHub secrets:

| Item | Example |
|------|---------|
| Keystore file | `~/theorem-android.jks` |
| Alias | `theorem-release-key` |
| Keystore password | `theorem-sign` |
| Key password | `theorem-sign` (same if you pressed Enter) |

### Encode the keystore for GitHub

```bash
base64 -w0 ~/theorem-android.jks
```

This prints a single long line of text. Copy it — this is the keystore FILE
encoded into a string that can be stored as a GitHub secret.

### Store in GitHub repository secrets

Go to Github repo → Settings → Secrets and variables → Actions → Secrets.
There are 5 secrets needed. Here is what each one is:

| Secret | What it is | Value to set |
|--------|------------|--------------|
| `ANDROID_KEY_BASE64` | The keystore **file** encoded as base64 | Paste the string from `base64 -w0 ~/theorem-android.jks` |
| `ANDROID_KEYSTORE_BASE64` | **Same thing** — alternative name the CI checks as fallback | Paste the **same** base64 string |
| `ANDROID_KEYSTORE_PASSWORD` | The password that unlocks the **keystore file** | `theorem-sign` (or whatever you chose at prompt 1) |
| `ANDROID_KEY_ALIAS` | Which key **inside** the keystore to use | `theorem-release-key` |
| `ANDROID_KEY_PASSWORD` | The password that unlocks that specific **key** | `theorem-sign` (the value from prompt 10) |

> **Why two base64 secrets?** The CI checks `ANDROID_KEY_BASE64` first, then falls
> back to `ANDROID_KEYSTORE_BASE64` if the first is empty. Set both to the same
> value for compatibility. This is a legacy artifact.

> **Why two passwords?** `ANDROID_KEYSTORE_PASSWORD` unlocks the file.
> `ANDROID_KEY_PASSWORD` unlocks the key inside. If you pressed Enter at prompt
> 10, they are the same value. If `ANDROID_KEYSTORE_PASSWORD` is empty, CI falls
> back to `ANDROID_KEY_PASSWORD`.

### Securely back up the keystore

1. Copy `theorem-android.jks` to a secure location (KeePass, encrypted USB, etc.)
2. Store the alias and both passwords alongside it
3. **Losing this keystore means you cannot update your app on users' devices who installed from GitHub releases.** Before uploading to Play Store for the first time, ensure you have at least two backups.

### Rotating keys

Since Theorem is not yet on the Play Store, there is no user-base constraint on the signing
key. If the current key is lost:

1. Generate a new keystore (see above)
2. Update the GitHub secrets with the new values
3. Users will need to uninstall the old app before installing the new one (different signature)

**After the first Play Store release**, key rotation is only possible through the
[Play Console's key upgrade process](https://support.google.com/googleplay/android-developer/answer/9842756).
Treat your upload keystore as irreplaceable from that point forward.



## 3. Consistency Between Local and CI Builds

Both keys should **never be committed to the repository**. Use GitHub Secrets for CI and
keep local copies secure.

For local release builds, set the environment variables before running `pnpm tauri build`:

```bash
# Updater signing
export TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.tauri/theorem.key)"

# Android signing (handled via keystore.properties, not env vars)
# CI auto-creates src-tauri/gen/android/keystore.properties — for local,
# copy that file from CI output or create it manually:
#   storeFile=/path/to/theorem-android.jks
#   keyAlias=theorem-release-key
#   password=your-password
```

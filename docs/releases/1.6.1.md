# 1.6.1 prerelease preparation

Planned release date: 2026-11-03. Publish `v1.6.1` as a **prerelease**, following
Theorem's rule that only `X.Y.0` releases are stable. The five version files
already agree on `1.6.1`.

## Release-note summary

- Reading-first setup, flexible weekly goals, lasting reading XP and levels,
  and clearer Statistics. Existing reading history is retained and credited.
- Optional Discover and Feeds navigation on each device (#173), and attached
  highlight notes correctly included in Workbench Notes (#170).
- Daily Review dismissal survives restarts; book covers download and validate
  through the native image pipeline.
- Improved audiobook controls, metadata and chapter support, plus terminal
  chapter titles and Unicode-safe labels.
- Local discovery on laptop hotspots without an internet relay.
- Refreshed desktop/phone screenshots using public-domain books and cultural
  feeds, with source credits and a placement guide.

The complete change list remains in [CHANGELOG.md](../../CHANGELOG.md).

## Publication checklist

Follow [the release runbook](../release.md) at the final release revision:

- Review and commit the product images, landing images and harness changes.
- Include the intended release commits on `main` before tagging.
- Run every release gate, including Foliate reproduction, both Android clippy
  targets and the complete native E2E suite. Use a fixed E2E binary when other
  Cargo commands could replace the default executable.
- Regenerate icons from `public/favicon.svg` and review any resulting changes.
- Date the `1.6.1` changelog entry for the actual publication day.
- With maintainer approval, create and push `v1.6.1`.
- Let every platform job finish, then verify the release is public and marked
  as a prerelease. A failed platform job leaves the release as a draft.

No tag or release is created by the screenshot tooling.
